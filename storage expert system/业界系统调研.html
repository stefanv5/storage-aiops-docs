资料核验于 2026-11-18。这里比较各产品能采什么数据、怎么分析和调查、能执行什么操作。要比较性能，需在相同的负载、权限和故障集下实测。公开资料缺少这类测试。

2026-11-21 的专题用写入延迟和卷扩容两道任务逐项对照各产品与 DME。见业界 AI 运维产品与华为 DME 对标。

0. 读法

按数据从设备或应用进入系统，到操作得到验证的顺序阅读。

设备/应用
   │ 遥测、日志、变更、拓扑
   ▼
采集与数据层（采集器/云/数据湖）
   │
   ▼
分析与知识层（基线/异常/预测/规则/知识库）
   │
   ▼
调查与工具层（Copilot/Agent/MCP/查询）
   │
   ▼
动作与验证层（工单/编排/审批/回滚）

对照产品资料，查清五件事。

  1. 数据来自设备还是应用？能导出原始数据吗？
  2. 用规则、统计、预测还是大模型（LLM）分析？有没有公开评测指标？
  3. 查询工具的输入和输出有没有说明？能追到证据来源和采集时间吗？
  4. 能查询、提建议、经审批执行，还是自动执行？谁有权限？失败后怎么恢复？
  5. 评测有没有公开故障集、用于检验误报的无故障样本，或隐藏答案的测试？

1. 主模板：Everpure Pure1 + Fusion

架构：

FlashArray/FlashBlade
   │ 遥测/健康/容量/性能
   ▼
Pure1（设备群管理面、AI Copilot、MCP Server）
   │ 只读查询
   ├─ 站点/租户/设备群健康
   └─ 容量/性能/告警

Fusion（阵列内部关系）
   ├─ 阵列/卷/文件系统/工作负载/预设/拓扑
   ├─ 部分性能查询需直连令牌
   └─ 可选写工具（默认关闭，启用后核对确认设置）

Pure1 用来找异常设备，内置 AI Copilot。外部 Agent 可分别接入 Pure1 Manage MCP 和 Fusion MCP。Fusion 可查具体的卷、工作负载及其共享资源。Fusion 2.0 的写工具默认关闭。启用后受阵列令牌和服务端确认设置约束。默认要求客户端支持确认，也可由管理员另行关闭。普通批准和拒绝记录在 INFO，排查时要核对日志级别。

在这个模拟例子里，Pure1 显示 array-3 的前端延迟升高。Fusion 查到 orders-vol 与 backup-vol 在同一阵列，变更记录显示备份于 02:12 启动。先比较两个卷的负载、共享的端口和控制器，再查网络和设备指标，判断是否争用。

公开资料列出了工具和查询。Copilot 的内部模型以及根因分析（RCA）准确率没有公开。写工具的实际权限取决于部署版本、工具清单和令牌。

2. NetApp AutoSupport + Digital Advisor

架构：

ONTAP 集群
   │ AutoSupport（遥测/日志/配置）
   ▼
Active IQ（资产、合同、版本、风险规则）
   ├─ 健康/风险
   ├─ 容量趋势
   └─ 升级/生命周期建议
        │
        ▼
Digital Advisor（看板/报告/建议）

AutoSupport 把设备遥测、配置和日志送到云端。Active IQ 核对设备、版本、支持合同和风险规则。Digital Advisor 据此提示风险、给出容量和升级建议。

卷已用 80%，近几周每周增加 2 个百分点。按这个速度，约 5 周达到 90%。再查合同和版本支持期限，决定先扩容还是先升级。

风险规则和建议的依据、误报率、模型细节均未公开。用厂商提供的容量趋势做计划时，还要核对本地增长和业务变化。

3. NetApp Data Infrastructure Insights（DII）

架构：

多源数据（ONTAP/E-Series/StorageGRID/交换机/VMware/云）
   │ 采集器
   ▼
DII 数据层（资产、性能、容量、日志、告警、采集健康）
   ├─ Monitor（阈值/异常/容量/性能）
   ├─ 看板/报告
   └─ MCP（Preview，租户内只读）

用 DII 先查采集单元、数据源和资产样本，再查容量和性能。原厂配方使用 AcquisitionUnitsService_getAcquisitionUnits 和 CollectorService_getDataSources 等。collection_status 可作为自建汇总工具。MCP 处于预览阶段（Preview），只提供租户内的查询权限。

阵列性能异常，3 个采集器中有 1 个断连。先查断连影响哪些资产、最后何时采到数据。标出没有数据的卷，用其余卷的数据继续调查。

MCP 的工具和权限以对应版本文档为准。Monitor 生成事件和告警，根因还需调查。

4. 华为 iMaster DME / DME IQ / DataMaster

架构：

存储/交换机/服务器/虚拟化/容器
   │ 南向 REST/SNMP/SSH/CSI
   ▼
DME（配置库/历史库/搜索/告警/拓扑/智能分析/智能体/编排）
   │ 北向 REST/SNMP/Ansible/CSI
   ▼
云管/ITSM/自建平台

另一条云服务链：DME IQ（移动 APP、Call Home、工单、在线客服、预测）

DME 管理设备。产品页列出 DataMaster 的对话式运维和故障 Agent。博客还介绍了优化 Agent、本地与云端联动，需核实这些能力是否随 25.1.0 交付。DME IQ 的资料另外介绍了云端预测和远程支持。

25.1.0 白皮书列出多厂商设备管理、SAN/NAS/容器拓扑、I/O 路径、故障树和健康评分。预测周期分别为容量 1 年、性能 2 周、硬盘健康度 14 天、特定 SAS HDD 故障 30 天。白皮书称故障智能体覆盖 64% 的闪存故障场景。性能记录按分钟保留 7 天、按半小时保留 6 个月、按天保留 2 年。受支持的 Dorado V6 及后续设备要预先开启 5 秒历史留存，设备侧最长保留一周。DME 自身不保存该粒度的历史。彩页称最多管理 175 套存储，现场能纳管多少套，按部署规格核对。

容量超过阈值后，查健康扣分和容量预测。预测最多用过去 180 天的数据，向前看 1 年。如需扩容，提交地端待办或已接入的 ITSM 审批。发放资源后查水位、业务和保护。DME IQ 的云工单用于支持场景。实时跟踪进度需绑定华为维保服务，地端审批按本地角色和接入配置执行。

厂商公布了 80%、5 倍、90% 和 1/3/5 分钟等指标。测试集和误报率未公开。交通银行联合项目的资料也提到知识图谱，标准版的图谱接口和通用 MCP 是否交付需单独核对。详见DME 解剖。

5. Dell AIOps / PowerStore

架构：

PowerStore
   ├─ 本地 Manager（4.2）：设备性能历史区间和偏离点，无直接告警
   ├─ Support Connectivity + 云端接入 → Dell AIOps：健康、趋势和建议
   └─ Health Checks：4.2 起检查包纳入 RxDefinitions，并可对指定问题开启 Auto-Repair

本地视图只标出设备性能偏离。云端分析取决于接入和已上传的数据，可查健康、资源争用或容量突增。助手按账号和设备范围给建议。Health Checks 只对支持的已知问题按配置告警或自动修复。

卷用量在 24 小时内增加 20%，每秒 I/O 次数（IOPS）没变。先查快照、克隆和日志，再核对应用变化和变更记录，找出增长原因。

评分模型、权重、误报率未公开。GenAI 的回答是否引用来源也未公开。

6. AWS DevOps Agent

架构：

Agent Space
   ├─ 应用拓扑（服务/资源/依赖）
   ├─ 告警/日志/指标/变更
   ├─ 调查工具（只读 AWS API）
   └─ 沙箱（临时环境、网络白名单）
        │
        ▼
   调查结论/证据/建议

Agent Space 限定 Agent 能查看的应用、账号和数据。调查时，Agent 把应用症状、基础设施记录、变更和日志放到同一时间线上。调查沙箱使用只读权限和网络允许列表，限制可访问的范围。服务卡列出了评估方法、角色和限制。

部署后 5 分钟，错误率升高。先查部署范围、配置、下游依赖和日志。若需修改生产资源，要另行启用定向动作，再走授权和审批。

能查到哪些系统取决于已接入哪些工具。阵列内部状态由原厂或自建工具提供。定向写操作默认关闭。

7. 横向对比

系统 优先用它解决的问题 相对 DME 的优点与代价
Everpure Pure1 + Fusion 让不同 Agent 访问设备群资源和受控操作 开源工具更容易做兼容和权限测试。阵列性能覆盖与直连配置有关，适用原厂设备
NetApp Digital Advisor / DII 做风险规划及核对不同设备是否采到了数据 采集状态、字段和查询限制明确。DII MCP 是只读 Preview，设备写入依赖另外的工具
华为 DME 看 OceanStor I/O 路径，结合故障树和工作台处理设备问题 有原厂设备数据和处置流程。能否关联应用、网络等外部证据，以及如何核对外部操作结果，要在现场验证
Dell AIOps / PowerStore 复核历史区间偏离、共享资源争用与容量变化 本地可查 I/O 大小，可调整时间范围和检测灵敏度。云端能力取决于连接和上传的数据
AWS DevOps Agent 从应用变更和依赖追到基础设施，检验两次调查的差别 可比较调查时间线、工具和评分。阵列内部信号须额外接入，回放查询在线数据
Datadog Bits 从应用告警开始调查，经资源授权后处置并复查 可在同一次调查中查看处置和复查记录。操作受预览范围和资源权限限制。设备冗余由存储侧核对

案例对照和现场验收条件见业界 AI 运维产品与华为 DME 对标。

8. 2026 年值得跟进的工程变化

  1. Pure1、Fusion 和 DII 都提供 Agent 可调用的查询工具。用这些工具调查时，先确认采集正常，再按时间和对象缩小范围。
  2. AIOpsLab、RCAEval 和 ORCA-bench 评测检测、定位、诊断、缓解和证据。它们主要覆盖云和微服务。存储场景仍需补充 Ceph 归置组（PG）、磁盘、容量、协议和故障域案例。
  3. FAST ’20 和 Backblaze 的数据可用来检验预测方法。换用 SSD、新固件或新维护策略时，要重新收集故障标签并校准模型。

补充阅读顺序

  1. 先读 Pure1 说明与 Fusion 用户指南的 Understand → Use → Act，记录每个工具能查哪些资源、需要什么权限、缺哪些数据，执行前还要满足哪些条件。
  2. 读 DII MCP 的 “What you can investigate” 和 “Choose an entry point”，从容量、性能和采集状态各挑一个问题，列出回答所需的最少查询。
  3. 先读 AWS 服务卡的评估方法和角色，再看 AIOpsLab 的任务定义。为 Ceph 事故写出定位要求、所需证据和处置验收标准。
  4. 读 DME 白皮书的智能分析/智能体/预测章节，对照 DME 解剖的准备工作和九个运维环节，标出已交付、公开资料未说明和需自建的功能。
