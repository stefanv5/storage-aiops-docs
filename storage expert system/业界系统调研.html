0. 读法

每个系统都按同一张“五层图”拆：

设备/应用
   │ 遥测、日志、变更、拓扑
   ▼
采集与数据层（采集器/云/数据湖）
   │
   ▼
分析与知识层（基线/异常/预测/规则/知识库）
   │
   ▼
调查与工具层（Copilot/Agent/MCP/查询）
   │
   ▼
动作与验证层（工单/编排/审批/回滚）

看一个产品时，先问五个问题：

  1. 数据是设备侧还是应用侧？原始数据能不能导出？
  2. 分析是规则、统计、预测还是 LLM？有没有公开指标？
  3. 调查有没有工具契约/证据/时间语义？
  4. 动作是只读、建议、受监督还是自动？权限/回滚是什么？
  5. 评测有没有公开故障集/负对照/盲评？

1. 主模板：Everpure Pure1 + Fusion

架构：

FlashArray/FlashBlade
   │ 遥测/健康/容量/性能
   ▼
Pure1（设备群管理面、AI Copilot、MCP Server）
   │ 只读查询
   ├─ 站点/租户/设备群健康
   └─ 容量/性能/告警

Fusion（阵列内部关系）
   ├─ 阵列/卷/文件系统/工作负载/预设/拓扑
   ├─ 部分性能查询需直连令牌
   └─ 可选受监督写工具（默认隐藏，需配置）

机制：Pure1 解决“哪片设备群不健康”，Fusion 解决“哪个卷/工作负载、和谁共享”。MCP 把查询变成有 schema 的工具，Copilot/Agent 通过工具拿事实；写工具默认隐藏，调查与处置分开授权。

例子：订单延迟升高 → Pure1 找到 array-3 前端延迟高 → Fusion 找到 orders-vol 与 backup-vol 同池 → 查变更发现备份 02:12 启动 → 形成“共享后端争用”假设，并列网络/磁盘/负载反证。

证据边界：Pure1/Fusion 的公开资料能证明“有这些工具/查询”，不能证明 Copilot 的内部模型、通用 RCA 准确率；写工具权限要以部署版本、工具清单、令牌为准。

2. NetApp AutoSupport + Digital Advisor

架构：

ONTAP 集群
   │ AutoSupport（遥测/日志/配置）
   ▼
Active IQ（资产、合同、版本、风险规则）
   ├─ 健康/风险
   ├─ 容量趋势
   └─ 升级/生命周期建议
        │
        ▼
Digital Advisor（看板/报告/建议）

机制：AutoSupport 把遥测与配置/日志一起送云端；Active IQ 把设备、版本、支持合同、风险规则关联；Digital Advisor 输出风险、容量、升级建议。它强在“资产 + 合同 + 版本”的联合判断，不是单一 ML。

例子：卷已用 80%，近几周每周增加 2 个百分点。若趋势持续，约 5 周将达到 90%。再对照合同与版本支持期限，决定扩容和升级的先后。

证据边界：风险规则/建议的依据、误报率、模型细节未公开；容量趋势是厂商口径，需结合本地增长和业务变化。

3. NetApp Data Infrastructure Insights（DII）

架构：

多源数据（ONTAP/E-Series/StorageGRID/交换机/VMware/云）
   │ 采集器
   ▼
DII 数据层（资产、性能、容量、日志、告警、采集健康）
   ├─ Monitor（阈值/异常/容量/性能）
   ├─ 看板/报告
   └─ MCP（Preview，租户内只读）

机制：DII 把“采集健康/资产身份”作为可查询对象，先验证数据齐全，再查容量/性能。MCP 当前是 Preview，工具范围是租户内只读；适合调查，不适合处置。

例子：阵列性能异常，同时 3 个采集器有 1 个断连。查询受影响对象和最后采集时间，标注哪些卷缺测，再分析可见子集。

证据边界：MCP 是 Preview，工具清单/权限以当前文档为准；Monitor 的输出是事件/告警，不是自动根因。

4. 华为 iMaster DME / DME IQ / DataMaster

架构：

存储/交换机/服务器/虚拟化/容器
   │ 南向 REST/SNMP/SSH/CSI
   ▼
DME（配置库/历史库/搜索/告警/拓扑/智能分析/智能体/编排）
   │ 北向 REST/SNMP/Ansible/CSI
   ▼
云管/ITSM/自建平台

另一条云服务链：DME IQ（移动 APP、Call Home、工单、在线客服、预测）

机制：DME 是设备侧管理面，DataMaster 的对话式运维和故障 Agent 见产品页。优化 Agent、云地协同见博客，25.1.0 交付范围待核实。DME IQ 另有云端预测和远程支持说明。25.1.0 白皮书披露多厂商纳管、SAN/NAS/容器拓扑、I/O 路径与故障树、健康评分、容量 1 年、性能 2 周、硬盘健康度 14 天和特定 SAS HDD 故障 30 天。白皮书称故障智能体覆盖 64% 的闪存故障场景，并列出分钟级 7 天、30 分钟 6 个月、天级 2 年的性能保留。最大 175 套存储来自彩页，实际规模依部署规格确认。

例子：容量告警 → 健康扣分 → 容量预测（180 天→1 年）→ 扩容建议/工单 → 审批 → 资源发放 → 验证水位。

证据边界：厂商指标（80%/5 倍/90%/1-3-5 分钟）没有公开测试集/误报率；知识图谱还出现在交通银行联合项目披露中，标准版图谱契约和通用 MCP 交付需单独核对。逐环节见DME 解剖。

5. Dell AIOps / PowerStore

架构：

PowerStore/基础设施
   │ 遥测/性能/容量/告警
   ▼
Dell AIOps（CloudIQ 类）
   ├─ 健康评分
   ├─ 预测分析
   ├─ 性能基线/资源争用/容量突增
   └─ GenAI Assistant
        │
        ▼
分级响应/工单/报告

机制：健康评分是多指标加权/扣分；性能分析把历史基线、资源争用、容量突增分开；GenAI Assistant 负责解释/建议。健康分是入口，不是根因。

例子：卷容量 24 小时突增 20%、IOPS 不变 → 提示容量异常增长，建议查快照/克隆/日志；为什么增长仍要查应用/变更。

证据边界：评分模型/权重/误报未公开；GenAI 回答是否有来源引用未公开。

6. AWS DevOps Agent

架构：

Agent Space
   ├─ 应用拓扑（服务/资源/依赖）
   ├─ 告警/日志/指标/变更
   ├─ 调查工具（只读 AWS API）
   └─ 沙箱（临时环境、网络白名单）
        │
        ▼
   调查结论/证据/建议

机制：Agent Space 限定可见应用/账号/数据；跨源调查把应用症状与基础设施/变更/日志放同一时间线；沙箱只读 + 网络白名单限制爆炸半径。服务卡说明评估口径/角色/限制。

例子：部署后 5 分钟错误率升，先查部署范围、配置、下游依赖和日志。若建议修改生产资源，走另行启用的定向动作、授权与审批流程。

证据边界：跨栈覆盖随集成变化。阵列内部状态须通过原厂或自建工具提供，定向写操作默认关闭。

7. 横向对比

系统 优先用它解决的问题 相对 DME 的优点与代价
Everpure Pure1 + Fusion 让不同 Agent 访问设备群资源和受控操作 开源工具更容易做兼容和权限测试。阵列性能覆盖与直连配置有关，适用原厂设备
NetApp Digital Advisor / DII 做风险规划及异构采集覆盖检查 采集状态、字段和查询限制明确。DII MCP 是只读 Preview，设备写入依赖另外的工具
华为 DME 看 OceanStor I/O 路径，结合故障树和工作台处理设备问题 设备侧信号和原厂流程强。跨域证据和外部执行对账要按现场验证
Dell AIOps / PowerStore 复核历史区间偏离、共享资源争用与容量变化 本地视图有 I/O 大小、灵敏度与时间。云端能力依赖连接和数据范围
AWS DevOps Agent 从应用变更和依赖追到基础设施，检验两次调查的差别 可比较调查时间线、工具和评分。阵列内部信号须额外接入，回放查询在线数据
Datadog Bits 把应用侧调查、按资源授权、处置和复查接起来 处置历史与恢复复查在同一流程。动作有 Preview 及资源限制，设备冗余仍由存储侧核对

案例对照和现场验收条件见业界 AI 运维产品与华为 DME 对标。

8. 2026 年值得跟进的工程变化

  1. 存储工具进入 Agent 调查路径：Pure1/Fusion/DII 都在把查询工具化；可迁移的是“先验证采集健康，再窄范围查询”。
  2. 评测从答案延伸到轨迹：AIOpsLab/RCAEval/ORCA-bench 把检测、定位、诊断、缓解、证据纳入任务；但主要覆盖云/微服务，存储要自建 PG/磁盘/容量/协议/故障域案例。
  3. 预测仍要适配真实设备：FAST ’20/Backblaze 适合方法验证；迁移到 SSD/新固件/新维护策略要重新收集标签和校准。

  1. 先读 Pure1 说明与 Fusion 用户指南的 Understand → Use → Act，记录每个工具能返回的实体、权限、数据缺口、动作前置条件。
