华为 DME 与 DataMaster

收到慢写报障后，值班员可从卷、主机或告警进入 DME，沿可见 I/O 路径查受影响的设备与端口。设备和智能分析提供指标与诊断结果，DataMaster 调工具并汇总报告。 H

DME 25.1.0 容器版已公开功能

  1. 资源纳管。 登记阵列与资源关系。通过受支持的 REST、SNMP 等采集库存、性能与告警。按兼容清单连接 SAN 交换机、主机、虚拟化和 Kubernetes 等环境。验收时分别记录可发现、可监控、可诊断和可操作的型号范围。
  2. 设备性能。 可从存储设备、池、LUN、磁盘、前端端口等对象查看相应性能。支持历史曲线和两个时间窗对比。受支持的 Dorado V6 及后续系列可按需回取设备侧留存的 5 秒数据，白皮书所述最大查看周期为一周。设备侧需提前开启相应留存。DME 自身不保存该粒度的历史，另行核对平台长期库的采样间隔。
  3. 告警与预警。 查告警、趋势异常或容量风险时，记录对象、计算窗口和适用设备。白皮书所说的 64% 指故障智能体覆盖的闪存故障场景。相关主机和交换机等资源在该能力的覆盖范围之外。DME 能纳管、能做性能分析的设备范围需另查。
  4. 智能分析。 慢写沿 I/O 路径查时延、瓶颈、设备异常和配置。OceanStor A 系列或分布式存储的受支持场景中，发生 I/O 错误并导致业务中断时，可用首错模块缩小范围。故障树用关联告警推断故障怎样传播。报告可给出候选根因、传播路径和处置建议。每个结论是否能通过接口追到原始样本，需现场验证。
  5. 对话和告警调查。 运维助手按对象和时间窗查指标、查健康，也能启动智能分析。故障智能体匹配场景后查健康、关联告警、瓶颈、风险和故障树。白皮书写明可用北向 API 对接客户的跨域智能体。接入时实查返回字段、角色、可见对象及任务状态。
  6. 作业与审批。 资源发放覆盖受支持的块和文件场景。待办任务可分组、预检参数、按地端角色审核，也可在满足条件时定期执行。工作流可跟踪预检、主流程和异常流程。工作台可做诊断和恢复，部分自定义动作限指定角色。测试接口或 ITSM 时，核对审批能否绑定跨系统计划，以及超时后能否找回原厂作业。

联合项目的另一条跨域链

交通银行联合项目采用 1+1+N。一个决策引擎查知识图谱和检索增强生成（RAG），一个编排服务调度计算、存储和基础设施等 Agent。常见故障匹配规则，复杂故障结合统计特征、语义编码、大模型和故障知识图谱。例如存储规则触发后，编排服务可派发只读查询，再按值班流程审批。目标部署的任务接口、知识库和设备能力需逐项核实。

DME IQ 提供云运维、Call Home 和支持工单，实时跟踪需绑定华为维保服务。地端作业由 DME 待办或已接入的 ITSM 审批。断开云连接后，再测地端查询、审批和云工单分别能否继续。 H

OceanStor 为主时，先用 DME 查哪条路径异常、有哪些设备证据、可走哪个工作流。业务 SLO、部署记录和各站点的历史拓扑可由总控接入。

Everpure Pure1 与 Fusion 2.0

Pure1 Manage MCP 查设备群，Fusion MCP 查已连接阵列的对象和配置。同一个 AI 客户端可分别接入两套工具。设备覆盖和权限各自核对。内置 Copilot 可单独发起调查。 E

  1. 管理面盘点。 Pure1 Manage MCP 正式可用，开放受支持的只读 Pure1 Manage API。适于先找告警、容量风险和异常设备群。Pure1 自带 Copilot 另有性能异常调查功能。
  2. 发现应用关系。 厂商介绍 Purity 6.10.0 在适用阵列上发现支持的数据库应用与文件上下文，可补充应用、工作负载与存储的关联。事故中的实际发布、业务请求或远端调用还需相应应用观测。
  3. 阵列层工具。 Fusion 提供设备群、阵列、FlashArray 卷、文件系统、工作负载和预设查询。可用专用工具查 IOPS、吞吐及时延，也有通用只读配置查询。设备群总览列得出的成员，可能多于已配置性能查询的成员。
  4. 配置与工作负载操作。 Fusion 2.0 区分精选写工具与通用写工具，两类默认关闭。精选工具覆盖文档列出的放置建议、预设、部署、卷、主机及快照等操作，具体支持按阵列类型确认。
  5. 确认与记录。 保留默认服务端确认时，不支持 MCP 询问交互的客户端会被拒绝。管理员可关闭这项确认。确认只覆盖经 Fusion 发出的写入，阵列令牌仍限制权限。要查普通批准和拒绝，查看 INFO 日志，默认 WARN 不记录两者。用会话 ID 和工具来源关联阵列请求，再接工单审批和业务验收。

与 DME 对照。 Fusion 给出了版本固定的工具和参数，可以直接验证“八台可见，哪五台能查性能”“没有确认功能的客户端会如何失败”。代价是 Token 覆盖、版本与 Agent 集成需要维护。DME 在 OceanStor 的 I/O 路径、故障树、受支持中断的首错和工作台更接近存储值班端。可对照 Fusion 的能力测试方法验收 DME API，保留 DME 原厂诊断深度。 E · H

NetApp DII 与 Digital Advisor

DII 把多个来源的资源和指标放在一起查。Digital Advisor 使用受支持的 ONTAP AutoSupport 遥测，给出风险、扩容和升级建议。两者可同时使用，数据源和许可分别核对。 N

  1. Digital Advisor 规划。 将设备遥测与诊断信息用于健康、风险、容量、性能和升级规划。适合评估某设备是否有已知风险，以及怎样安排升级或扩容。
  2. DII 异构接入。 通过受支持的采集单元及采集器获取存储、交换机、虚拟化、容器等对象。先核对型号和实际字段。带有 GPU 或 HPC 需求时，可查看 11 月更新记录中 NVIDIA Base Command Manager 采集器的预览范围。
  3. 先查采集。 原厂配方用 AcquisitionUnitsService_getAcquisitionUnits 查采集单元和最后上报时间，用 CollectorService_getDataSources 查数据源和最后成功采集时间。接入方可自建 collection_status，汇总这两项及授权台账内的样本覆盖。没有可靠分母时记 unknown_coverage。
  4. 查询约束。 先查可用的对象类型和字段，再选目标对象。事故窗口和健康窗口用相同单位和粒度，配方的单次窗口不超过 30 天。再查告警、日志和事发时的关系。报告写清查到的数据、据此推断的原因及缺口。
  5. 两个 AI 入口。 DII Assistant 在所述 AWS 托管站点正式可用，发布记录披露按问题生成可视化。面向外部 Agent 的 DII MCP 仍为租户内只读 Preview。调查完成后把设备写操作交给具有目标设备权限的工作流。

与 DME 对照。 对一套混合阵列和交换机环境，DII 提供了从采集单元、字段到实体查询的公开验证流程。DME 也纳管受支持的异构资产，在 OceanStor 上另具路径诊断和设备作业。在同一测试租户分别模拟采集单元在线但从未上报、最近一次采集已过期、部分卷缺样本和权限不足。核对各家能否给出可披露的缺测卷、最后采集时间和缺失字段。采集器在线比例与资产样本覆盖率分别算。 N · H

Dell PowerStore 与 Dell AIOps

PowerStoreOS 4.2 有本地异常视图。云端 AIOps 提供分析建议，设备 Health Checks 可处理指定的已知问题。部署时分别核对可查指标、建议范围和自动修复清单。 L

  1. 历史区间。 PowerStore Manager 用设备历史和周期变化计算预期范围。时延、IOPS、带宽或 I/O 大小超出范围时，图上会标出偏离值和时间，可调灵敏度。该视图只标记异常点。4.2 手册中的设备（appliance）视图，近 24 小时或一周按 5 分钟显示，近两周或一月按一小时显示。单卷和高精度数据要查相应性能视图及保留期。
  2. 同一请求数下的负载量。 例如写 IOPS 近似不变、均写大小从 8 KiB 到 64 KiB，则提交字节量约扩大八倍。再看同设备不同卷是否同步恶化、网络是否拥塞和是否有其他变更，判断是单一负载还是资源争用。设备级聚合可能隐藏单卷尖峰。
  3. 连接云端。 在支持的设备上开启 Support Connectivity 并接通 AIOps 后，可上传性能、容量、告警、配置和支持数据。基于上传的数据比较跨设备健康和趋势，接入需要按现场遥测出域要求验证。
  4. 云端分析。 关注容量突增、性能波动与争用。公开健康评分说明按影响最大问题扣分，风险分用于队列排序，判断原因仍应下钻到具体对象和证据。
  5. 云端助手。 在适用账号可用 @系统名 指定已接入实例，查健康、异常、IOPS、时延和带宽，并用所述 PowerStore 更新建议能力做计划。按账号、站点、设备和指标验收。云端助手的建议与现场执行记录分别保存。
  6. 已知问题自动修复。 从 PowerStoreOS 4.2 起，RxDefinitions 并入 Health Check 包。Auto-Repair 也从 4.2 起可用于支持的已知问题。命中后按设置只告警（Alert Only）或自动修复。部分问题仍需人工处理。验收时查一项适用问题的告警和修复记录。普通慢写走诊断流程，云端助手按其功能范围提供建议。

清单由评估器保存，哈希校验整个源 CSV。模型只收到按权限和截止时间筛过的证据包，其中证据 ID 已换成随机审计 ID。另算证据包的哈希并保存 ID 映射。path、case_filter 和整份 CSV 由评估器保留。生产网关只能报告授权范围内的可用、暂缺和被过滤数据，越权时返回通用拒绝。按权限、实体、时间和固件筛选后，再做关键词和向量检索、去重和重排。后端逐条检查引用是否存在、能否访问、是否支持对应结论。比如 C06 只说明观察范围内没看到回填。要判断新版本是否引发事故，还需查发布记录和新旧实例。必要时交人工复核。 R

怎么取得可验收的准确率

  1. 评估取证。 固定同一批事故的原始证据、可查截止、权限、查询预算和模型配置。分别跑文档 RAG、只有快照、文档加快照、快照加只读工具，另用规则或原厂诊断作基线。记录各组查到的证据、耗时、成本和结果。
  2. 评估推理。 固定证据、文档顺序、工具回执和查询范围，只改模型或推理模式。各组独立启动，隔离上一轮会话、额外在线数据和答案标签。无法冻结输入时，本项记为不适用，另报产品原生试验。 原生端到端结果

分别标注事后确认的原因和截止时是否可判断。 审核人员用事后证据标 true_cause，再用固定的事故快照标 decidable_as_of 和当时应采取的做法。B 完整例和 B 缺网络例是同一起事故，事后原因相同。截止时，完整例可列优先候选，缺网络例应暂缓。根因未确认的记 unknown，仍可评估证据和是否该给结论。按原始事故、相似案例、站点和时间划分数据。同一起事故的变体留在同一组。盲测索引和会话排除复盘答案和会暴露标签的 ID。A/B/C 及缺数变体先用于流程试验。
