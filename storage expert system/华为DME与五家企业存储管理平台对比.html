对比对象和版本

五家友商取自 Gartner 2026 年 8 月 19 日《Magic Quadrant for Enterprise Storage Platforms》的领导者象限。该象限共六家，去掉华为，剩下 Dell Technologies、Everpure（原 Pure Storage）、HPE、IBM 和 NetApp。这个口径用来筛选企业存储厂商。Gartner 同时评估厂商的平台和服务，报告没有给这些运维产品排第一到第五。以下功能按各厂商的版本手册核对，资料截至 2026 年 11 月 27 日。报告及图示出处

每家都查三件事。管理台拿得到哪些数据？哪一层能改配置？谁确认业务恢复？云端监控、地端管理和阵列固件分别核对。举例说，PowerStore Manager 建卷算 Dell 设备层的能力，不能记成 Dell AIOps 云端直接写阵列。

Dell Dell AIOps（原 CloudIQ） 本地 Storage Resource Manager（SRM）查异构设备。PowerStore Manager 与 Unisphere 管设备。备份找 PowerProtect

DME 的长处和短处

DME 的长处在华为设备占多数、管理平台要放在机房的环境。 同一个地端入口能查受支持的阵列、主机和交换机，按存储 I/O 路径找故障，也能给常规块、文件发放走待办审核和设备预检。值班员少在设备界面、监控和工单间来回切换。DME IQ 能另走原厂支持，但机房里的角色审批与厂商云端工单是两条流程。华为资料

DME 的短处集中在接入以后。 发现第三方阵列和收到告警，只说明接通了第一层。选 DME 管混合机房时，要逐台查能不能读卷、主机映射和端口指标，能不能把故障定位到路径，能不能执行并跟踪变更。面向应用的错误率、请求链路和恢复验证也要从业务侧取得。要让外部 Agent 复核证据，华为公开资料还没列出与 NetApp DII MCP、Everpure Fusion MCP、IBM Storage Insights MCP 一样具体的工具输入输出，以及逐次调用的权限和记录格式。DME 可以先通过北向 API 接入，实际能取回哪些字段要逐项测试。华为资料 · NetApp 资料 · Everpure 资料 · IBM 资料

同样需要留在机房时，NetApp 和 IBM 也有选择。 ONTAP 环境可用本地 AIQUM 和 System Manager。IBM 可用本地 Spectrum Control 和 CSM，是否满足目标设备、许可、版本及断网要求仍要查。比较部署方式时，测的是断开外网后还能查哪些历史、能执行哪些作业，再考虑哪套产品更省事。NetApp 资料 · IBM 资料

DME 一次本地故障调查和变更怎么走

  1. 先定现场范围。 从目标 LUN 或文件系统起查。确认 FC 交换机、对端 WWN、主机映射等已经采到。需要回看短时异常时，确认目标 Dorado 是否已开启 5 秒历史。再并排查应用错误、主机多路径和阵列时延。地端 DME 查存储路径，应用数据要从监控系统来。
  2. 再选分析方法。 25.1.0 白皮书把高时延分析与首错分析分开。前者用于合适的慢 I/O 场景，后者只适用于支持的 OceanStor A 系列或分布式设备上的 I/O 错误。DME 能画主机、交换机和阵列的路径。白皮书列出的故障智能体范围同时排除了部分主机及交换机关联排查，以及对象、迁移、容灾和备份业务。图里有节点，仍要看该故障工具能否查到节点证据。
  3. 最后才改配置。 要发一个新卷，可在受支持环境按服务等级选池，预检 FC Zone 和主机映射，走待办及变更窗口。完成后核对设备实际映射和主机识别，再用应用探针查请求。直接从设备界面写入，以及外部脚本通过 REST 或 Ansible 写入，分别检查是否仍受同样的审批约束。DME IQ 的支持工单不能代替地端审批。
  4. Agent 最好先给证据。 让 DataMaster 先返回对象、事发时间和诊断报告，再尝试申请一项经批准的操作。交通银行的公开材料能证明华为参与了跨域对接，具体接入依赖双方的调度及 API。它适合作为集成参考。白皮书和已交付版本仍应单独核对，不按联合项目估算所有环境的自动恢复能力。华为资料

六套平台在值班时怎么用

从“某业务写入变慢”开始。下面每条路线都走到现场会用的工具。主机与应用的证据要按环境补上。

平台 先查什么 确认故障或风险后去哪操作
DME 在地端 DME 选受影响 LUN，沿可见的主机、交换机、端口、控制器和池查异常。再按目标阵列核对支持的慢 I/O 分析或首错报告 已定义的发放、分区配置等任务走 DME 待办或已集成的 ITSM。进设备或 DME 查作业，另用主机和应用数据验收
Dell 在 Dell AIOps 看多个受支持资产的健康、性能异常和容量。收到告警后，从相应 PowerStore 或 PowerMax 的设备管理界面查更细的计数器与动作 到设备管理面按权限改卷、调整保护策略或查作业。需要应用恢复时进入对应备份或复制工具
Everpure Pure1 查受影响的阵列和性能，再沿已纳入的 VM 或卷关联定位争用。扩容或放置规划要核对阵列负载和数据缩减口径 Fusion 在支持的设备间统一管理部分原生操作。高风险动作检查写工具是否开、令牌权限和确认设置，也可转阵列管理面
HPE 在 DSCC 看受支持的 HPE 设备，按 Array、Host、Volume 查告警及性能。适用的平台可用 InfoSight 的 VM 或存储分析补证据 在 Data Ops Manager 或该型号的本地管理面执行。Remote Copy、切换和恢复取决于存储型号及保护配置
IBM 在 Storage Insights Pro 看跨阵列的池、卷、主机及容量。若环境和采集器支持，再核对交换机和映射数据 按目标设备进入 Storage Virtualize 等工具。涉及跨站复制时，由 CSM 核对会话、复制状态和切换顺序
NetApp 本地 AIQUM 查 ONTAP 事件和集群对象。要查异构设备、应用拓扑或历史性能，再用已接入的 DII 用 AIQUM 发放受支持的 LUN 或共享，也可到 ONTAP System Manager 或授权 API 执行。DII 的 MCP 查询不承担设备写入

风险、故障和 AI

核对项目 华为 DME Dell Everpure HPE IBM NetApp
容量与备件 容量趋势、性能和硬盘模型各有适用对象。把风险盘型号及维保与备件库存对上 Dell AIOps 容量预测用于安排扩容。用设备侧余量检查是否因数据缩减、快照或复制保留改变 Pure1 追踪容量和性能趋势。Fusion 做原厂阵列选址时，核对候选阵列和保护要求 Data Ops Manager 查容量和性能历史。B10000 的 Workload Planner 可输入工作负载规模与增长，比较各设备的余量 Pro 区分设备、池的容量和增长。支持的 FlashSystem Grid 能按历史负载和预测评估迁移位置 AIQUM 查 ONTAP 容量事件、趋势和超限。DII 将所采集的不同设备放到一个口径核对，实际预测要看各设备数据
慢 I/O 怎样定位 支持场景下用路径分析看网络与存储段。首错分析用于特定系统的 I/O 中断。慢写与 I/O 中断看不同报告 支持的 Dell 阵列用 Performance Impact 区分负载变化与资源争用。PowerStoreOS 4.2 起支持 appliance 本地异常，定位卷或业务还需下钻 Pure1 先定位阵列，再核对卷或已连接的 VM。Fusion 的控制工具能回查设备指标，需另确认应用影响 DSCC 看设备/主机/卷，配置后看 VM 路径。InfoSight 在特定平台提供跨栈可见性 回到卷、池、控制器相关图，查看同一段时间其他卷是不是也慢。拓扑和遥测不齐时，不给应用根因 AIQUM 提供 ONTAP 性能事件。DII 用 SAN Analyzer 逐跳查问题，仍需主机路径与应用错误作对照
Agent 实际能用什么 DataMaster 有对话和故障分析。公开白皮书列场景与工具机制，博客列管理员确认后的优化流程。对外主要从北向接口核验 AIOps Assistant 能查产品资料或已纳管的环境对象。AIOps 观测 REST 为只读。设备 REST 另有写入与异步作业 Pure1 MCP 可读，Fusion MCP 有明确的工具和可选写步骤，按版本验证 DSCC 有任务 API，HPE 提供用第三方桥转 MCP 的开发示例。X10000 的对象存储 MCP 属于独立产品，照其手册核对 IBM 文档列出 Pro 的社区维护 MCP，工具读取告警、系统与组件指标。独立 FlashSystem.ai 可经批准从本地创建卷等对象 DII MCP 文档标为预览，查询限于租户、工具只读。用资源、性能和覆盖数据查证，设备变更另行授权
报告复核 值班员可按对象和时间回查 DME。要跨系统复核，实测导出原始指标、报告引用、当时的映射版本及调用记录 拿 AIOps 告警发生时间、设备作业 ID 和实际生效状态对账 留下 Fusion 工具、目标、确认记录和阵列结果。生产幂等、双人审批与应用验证另核对 核对 DSCC 的任务或活动记录，按产品补设备审计与主机结果 用 Pro 报表、事件和对象 ID 核对。涉及灾备时，还要找 CSM 会话记录 导出 DII 查询或工具结果，核对数据源、时间窗和范围。需额外验证权限撤销和历史回放

  • 排障先找哪台设备。 Dell AIOps 适合先扫一批 Dell 存储、服务器或网络资产的健康和性能。对已接入的 VMware、Connectrix，再查可见关系。PowerStore 的慢写问题落在某个 appliance 时，进入 PowerStore Manager 看本地异常时间窗和具体卷。PowerStoreOS 4.2 的本地异常检测有自己的 appliance 范围，不能按这项功能推断 Dell 所有阵列都能定位到应用。
  • 历史数据取哪一层。 Dell AIOps 白皮书列出系统级 5 分钟数据 100 天、对象级 22 天。DME 的普通分钟数据留 7 天，兼容华为阵列可以先开启 5 秒历史。这两个差异对应两个问题。查数周前的反复升高，先从 Dell 云端看能否按对象取回。查刚发生的短时抖动，PowerStore 本地还有秒级数据，手册列出秒级样本保留 1 小时。兼容 Dorado 的 5 秒历史需提前开启，最长一周。比较的是取数窗口和对象，不能把保存期限理解为厂商故障检测更快。
  • 高风险动作怎么卡。 PowerStore 4.3 的多方授权（MPA）针对受控的敏感操作，例如删除卷。启用后，UI、PSTCLI 和 REST 都受相应规则约束。异步 REST 可取作业记录，提交成功和执行成功可以分别核对。DME 的长处是能把服务等级选择、建 LUN、FC Zone 和映射放进面向坐席的待办流程。Dell 的长处是把某些危险动作拦在设备操作处。采购时用同一个删除动作验证两边的拦截点，以及能否绕开。

Everpure 如何为一批卷选阵列

  • 同一批卷怎么分配。 Pure1 适合先看阵列和性能。Fusion 在支持的原厂设备之间按工作负载、预设和放置要求选目标。把一批卷的性能和保护条件作为输入，再查看选中的阵列与不合格原因。DME 也能按服务等级选池并发放，它的长处是把路径、Zone 和发放任务接在一起。选哪套取决于主要工作是管理华为 FC/SAN，还是在 Everpure 设备群里统一安放卷。
  • 接 Agent 时怎样防误写。 Pure1 MCP 是读接口。Fusion MCP v2 把写操作做成可开启的工具，默认要确认。实际还要检查客户端能否交互确认、令牌权限和通用写工具是否开启。两类写开关默认关闭。保留默认确认且客户端无法交互时，写请求会被拒。指定高风险动作还要输入目标名。地端 DME 已经有待办、角色和设备 API，用外部 Agent 调这些接口时，需要采购方实测工具能否拿到同样清楚的范围和操作凭据。

HPE 的云管、只读和隔离部署

  • 外网该开到什么程度。 HPE Alletra Storage MP B10000 的 QuickSpecs 分别列出 DSCC 云管理、云端只读、工厂激活的隔离型单阵列，以及单独订购的 Disconnected 本地多阵列管理。云端只读由阵列本地限制，保留云端分析，同时拒绝云端写操作。必须在云端只读模式下用本地角色测试。DME 机房部署的长处是把监视、排障和部分审批放在一个平台。不能把这个长处写成 HPE 无法离线管理。

IBM 的异构监控、迁移和卷组复制

  • 混合阵列台账怎么做。 Storage Insights Pro 的支持表明确列出若干 Dell EMC、Hitachi、NetApp、Pure 和 Lenovo 设备，公布了探针和采样周期。评估 IBM 时，把目标型号填到矩阵里逐个复核，能从 Pro 跨阵列拿到存储池和容量的地方是优势。DME 对华为阵列和接入的 FC 路径查得细，但它对第三方阵列能否读到同样的指标与关系，要另外取证。IBM 的一部分第三方采样是 15 分钟，短时抖动不能靠这个间隔定位。

巴西环境部 NetApp FAS8040 故障，2024 年 3 月

巴西环境与气候变化部公开的采购附件收录了 3 月 17 日的运维邮件。15 日第一台控制器卡住，备用盘已经用完。16 日同一控制器再出问题，团队把业务移到第二台。邮件记录当时有七块盘退化。17 日第二台也无法维持服务，阵列上承载的业务中断。此前的风险已写进技术说明，事后团队提出补盘和迁移旧业务两条工作线。公开附件没有给出完整 I/O 计数器，无法算出第二台还有多少余量。采购材料及事故邮件

拿来比什么。 在 NetApp 同类受支持环境，可在 AIQUM 的聚合健康页核对备用数据盘有效类型、数量与容量，再用 ONTAP 的磁盘和高可用状态细查。用 DME 管支持的华为阵列时，查设备告警、盘状态、控制器负载、存储池和预测结果。在这台 FAS8040 上，DME 即使能看到第三方资产，也要拿实际版本证明有备用盘与控制器接管字段。IBM Storage Insights Pro 和 NetApp DII 适合拿来复测异构设备的可见性，具体字段仍受采集器和型号限制。

怎样验收。 先让平台报出“可用备用盘为零”，再查故障域和备件到货。用事发前负载核算接管后的控制器余量、重建速率和前台写入延迟，保留原厂命令的核对结果。预案中写上允许接管的上限和迁移条件。即使能提前发现风险盘，缺少备盘和迁移窗口仍会卡住恢复。

欧洲央行 TARGET 服务中断，2025 年 2 月 27 日

拿来比什么。 DME 可以用受支持场景的 I/O 路径、慢 I/O 分析和首错记录，先判断异常出现在阵列内还是路径上。在 Dell 环境，比 AIOps 告警能否定位到设备，再在 PowerStore Manager 等工具查端口和控制器。在 HPE 环境，比 InfoSight 或 DSCC 发现已有异常的输入，以及本地设备事件有没有比云端更早出现。三家都要拿 DB2 等待、主机路径和应用错误对照，未知硬件故障不能按宣传上的预测时间判定能发现。

Atlassian 批量误删客户站点，2022 年 4 月 5 日

原计划删除一款旧应用。交给执行团队的却是站点 ID，同一个接口也接受这种 ID。同行评审检查了脚本和接口使用方法，没检查 ID 对应的对象类型。883 个站点被删，涉及 775 个客户。Atlassian 当时已有不可变备份，并能恢复单个数据存储，但没有能批量恢复多站点、多个相互依赖产品的现成流程。官方报告称恢复点目标达成，恢复时限未达成。Atlassian 事故复盘

拿来比什么。 DME 的预检、待办审核和角色分离适合用来组织受支持的地端变更。Fusion MCP 可通过写工具开关、令牌和确认流程控制调用。IBM CSM 的复制会话可以保护受支持的卷组。三者解决的问题各不同。上层应用如果绕开管理台直接删除数据，存储工单无法替它审查输入，卷复制也不会自动识别业务对象被误删。

怎样验收。 提交一个租户错误、对象类型错误或数量超限的计划，要求执行前拒绝，并留下审批人、对象 ID 和实际生效范围。然后从保留副本恢复一批互相关联的实例，核对备份清单、应用身份、数据库和业务事务。分别记录找到可用恢复点花了多久、整批服务恢复花了多久。

Spring Branch 学区从 CrowdStrike 故障中恢复，2024 年 7 月 19 日

学区使用 Veeam 把备份写到 FlashBlade，另在灾备站保留 FlashArray//C 副本。Everpure 发布的客户案例记录，7 月 19 日补救尝试后，团队改用 Veeam 从 Everpure 备份恢复。学区的技术说明另提到 SafeMode 不可变快照。公开材料没有说明这次恢复逐一选用了哪些快照和异地副本。客户案例与技术说明

拿来比什么。 Everpure 方案的可验证优势是备份副本如何保留、异地如何提供恢复源。DME 地端可以查受支持的存储状态和保护策略。华为方案要另外确认 OceanProtect 或现有备份软件能否列出受影响的主机、提供干净恢复点，并执行恢复。Dell 也需要区分 AIOps 所见状态与 PowerProtect 的恢复步骤。IBM CSM 的复制状态回答的是卷组状态，应用能否恢复还需另验。

怎样验收。 让常用存储管理员尝试提前删除受保护副本，再从异地副本在隔离网络恢复一台服务。记录执行角色、恢复点、耗时和最终的登录或交易结果。缺任一项时，保护能力仍要继续验证。

Cloudflare Workers KV 多服务中断，2025 年 6 月 12 日

底层第三方云存储中断后，依赖 Workers KV 的认证、配置和分发服务受到影响。Cloudflare 记录影响持续 2 小时 28 分钟，Workers KV 约 90.22% 的请求失败，未发生数据丢失。已经命中缓存的部分请求仍能服务。最先发现问题的是 WARP 团队，他们看到新设备注册失败。其他服务随后告警，团队查到共享的 KV 依赖后合并处理。Cloudflare 复盘

拿来比什么。 DME 的 SAN、NAS 和容器拓扑用于查已经接入的本地路径。NetApp DII 的应用资产与拓扑对照能帮助追查已采集的依赖。IBM Storage Insights Pro、Dell AIOps、Pure1 与 HPE DSCC 也只能分析自己收到的数据。在第三方后端不可见的窗口，业务探针、各服务错误率、依赖调用和云厂商事件才是主要证据。

怎样验收。 在测试环境模拟后端访问失败，让两个业务同时报错。再单独遮住一条外部依赖的遥测，验证工具能否区分采集失败与正常信号。报告还要列出仍可服务的缓存路径，以及需要第三方补查的故障。以是否指出共同依赖和缺失证据评分。

选型时要求看哪些结果

先固定六套产品都能用的测试条件。用实际计划采购的型号、软件版本和许可。给每家同一份主机、交换机、阵列清单，允许使用它的原厂工具，但在结果里注明每一步在哪做，是否另购许可、依赖云或要开高权限。用相同测试负载、时间窗和故障脚本，结束后让工程师展示原始记录。
