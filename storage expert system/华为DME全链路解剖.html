[白皮书] 列出以下部署和接口要求。

  • ServiceMesh 服务化架构，分布式微服务，多节点下单节点故障仍可服务，可靠性 99.9%。
  • 对外提供 RESTful、SNMP、Kubernetes CSI 和 Ansible 等接口或插件。通过 SSH、SNMP 和 RESTful 管理存储、交换机和主机。
  • 支持物理机和虚拟化部署，操作系统包括 EulerOS（x86/ARM）、SUSE 15 SP7、RHEL 9.6 和 CTyunOS。
  • 支持单节点和多节点。跨数据中心管理要求 DME 到设备的时延 < 50 ms、丢包率 < 0.1%、带宽 ≥ 100 Mbit/s。DME 节点间分别要求 < 10 ms、< 0.1%、≥ 1 Gbit/s。
  • 25.1.0 暂不支持主备容灾。
  • 非结构化元数据节点 1–10 个，通过 NFS/CIFS/S3 采集元数据。
  • 许可按可用容量（TiB）计，闪存、分布式、备份和 AI 存储分别计费。试用期为 90 天。

2.3 这个架构意味着什么

[推断] DME 从设备管理接口读取聚合指标。业务 SLO 和客户端尾延迟需要通过应用埋点、OpenTelemetry（OTel）或 eBPF 等工具另行采集。

3.2 环节 1：请求路径与 SLO

DME 公开能力。 DME 从主机、网络到阵列查看设备侧 I/O 路径。

  • 沿 I/O 路径对比多个对象的指标，也可在同一张图显示。支持 1 小时、4 小时、12 小时、1 天、1 周、1 年或自定义粒度。
  • SAN 拓扑从 FC 交换机读取对端 WWN（光纤通道标识），匹配主机和存储的 WWN，再用华为存储的 HostLink 映射把物理端口连到逻辑资源。
  • NAS 拓扑：从华为存储取 IO trace，展示客户端到文件系统的访问关系；A 系列还支持 DataTurbo 客户端、Scaleout 网络拓扑。
  • 容器拓扑：依赖华为 CSI Driver，展示 Node/App/Workload/Pod/PVC/PV/存储单元。
  • 智能分析可查 I/O 路径时延、瓶颈、故障、亚健康和配置。A 系列可从并行客户端进入 zone，再沿业务网络、Scaleout 或存储 zone 的故障树找首个报错模块。报告覆盖计算、网络和存储。
  • 彩页口径：1 分钟识别、3 分钟定界、5 分钟辅助定位；秒级性能视图。

3.5 环节 4：异常检测、告警与健康评分

告警规则：

  • 屏蔽、闪断/振荡、汇聚、相关性（根因/衍生父子）、自动确认、标识（维护态/无效）、重定义（名称/级别/类别）、远程通知、告警同步、维护经验、事件转告警、名称组、HCS 全栈协同。
  • 北向上报可按告警 ID、源类型、级别、分类、根因父/子告警过滤，通过 SNMP Trap 送第三方。

检查策略：

  • 性能阈值（连续 N 个采样点超限）、容量阈值、可用性（硬盘健康、设备/端口/交换机/主机状态）、配置合规、可回收/低利用率资源。
  • 可设置检查周期，并指定所有条件都满足或任意条件满足时触发。可配置自动恢复动作，例如变更服务等级。
  • 巡检：预置每日关键风险项 + 自定义计划。

AI 健康：

  • 百分制扣分：告警、性能异常（基线对比、预测对比）、性能预警（过去 1 个月预测未来 2 周）、容量预警（过去 180 天预测未来 1 年）。

[推断] 从告警查触发的规则或检查项，再核对产品或用户设置的阈值和权重。误报率、召回率和校准结果未公开。

业界先进。 [原理] 多窗口 SLO 燃烧率可同时检查短期和持续异常。对大量指标做多重检验时，可用错误发现率（FDR）控制误报比例。还可按设备和负载分组建立基线，并用 Alertmanager 抑制关联告警。DII Monitor 可分别检查阈值、异常、容量和性能。Dell 提供健康评分、预测和生成式助手。Pure1 显示设备群健康。验收时一起衡量误报量和首次响应时间。

5. DME 的真实优势

从零替代 DME，需要自建以下能力。

  1. 设备覆盖和数据深度。 DME 可管理华为全系列和主流第三方存储，以及交换机、服务器、虚拟化和容器。HostLink、IO trace、CSI、端口光功率、控制器、池和 LUN 指标需要对应设备或平台接口。
  2. 故障树和领域知识。 智能分析沿 I/O 路径查首错模块、异常状态、配置和故障传播。产品页和彩页列出 80 多个检查项，白皮书称故障智能体覆盖 64% 的闪存故障场景。
  3. 自动化与预检查。 DME 支持资源发放、自动配置 Zone、安排变更窗口和 Ansible 编排。低权限角色规划任务，高权限角色审核。工作流可通过 API 调用。
  4. 云端支持与协同。 DME IQ 产品页列出 Call Home、工单、7×24 支持、移动运维、远程巡检和升级。DataMaster 的云端 MaaS 与本地工具协同来自博客描述，部署形态、数据流和驻留边界需确认。
  5. 真实设备数据。 华为用现场硬盘日志和故障样本训练模型，覆盖的设备及版本与公开数据集不同。公开资料未给出完整训练样本和版本范围。

9.3 与业界系统的对照

在 OceanStor 上做设备排障，先验证 DME 的 I/O 路径、故障树和工作台。Fusion 可对照外部工具与写入确认。DII 可对照不同设备的采集状态。PowerStore 可对照异常时间段和指标。AWS 可对照多源调查、记忆和回放。Datadog 可对照按资源授权和操作后复查。各产品的机制和版本出处见业界 AI 运维产品与华为 DME 对标。

交通银行联合项目公开了知识图谱、RAG、流程编排和多 Agent。采购或实施时，先核对目标版本是否交付这些能力。再挑一项设备操作，从调查记录查到 ITSM 审批和原厂作业，最后核对业务与保护验收。

10. 结论

  • OceanStor 为主时，优先用 DME 查设备、走故障树和执行已交付的工作流。诊断覆盖取决于设备型号、版本和故障场景。
  • 跨厂商使用时，核对业务 SLO、事发时的拓扑、外部工具接口、处置权限和事故回放。可通过现有北向 API 对接，也可封装为外部 Agent 可调用的工具。
  • 按目标版本确认博客提到的功能是否交付。用自己的事故回放集验收效果，并按现场权限控制每项操作。
